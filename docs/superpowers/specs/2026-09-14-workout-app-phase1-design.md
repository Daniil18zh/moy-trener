# «Мой тренер» — Фаза 1: ядро приложения

Дата: 2026-09-14
Статус: утверждён пользователем в чате, ожидает финальной проверки spec-файла

## Контекст и источник требований

Полное ТЗ — `~/Downloads/gym-app-prompt-for-claude-code.md` (см. также раздел «Источники» в нём). Проект признан слишком большим для одной спецификации (9+ подсистем), поэтому разбит на фазы. Этот документ описывает **Фазу 1** — минимальное работающее ядро, без которого остальные фазы не имеют смысла.

**Фаза 1** (этот документ): экран входа, онбординг/анкета, база упражнений, генератор программы, экран тренировки, хранение данных + экспорт/импорт JSON.

**Фаза 2** (отдельный спек позже): расписание, внутристраничные напоминания, экран прогресса/статистики (графики 1ПМ, тоннаж, стрик), смена единиц измерения и темы.

**Фаза 3** (отдельный спек позже): `manifest.json` + service worker, push-уведомления, полноценный PWA-режим вне iframe.

## Ключевые решения, принятые в брейнсторминге

1. **Стек**: Vite + TypeScript, без UI-фреймворка (React и т.п.) — минимальный бандл, простая ментальная модель, быстрая загрузка внутри iframe на Google Sites.
2. **Дефолтный логин/пароль**: используется значение из ТЗ (`danya` / `a0zOlB6rbhN914`) как есть — пользователь осознанно принял риск, что оно (в хэшированном виде) попадёт в публичный репозиторий GitHub Pages, и обязан сменить пароль при первом входе.
3. **Хранение**: только `localStorage` в Фазе 1 (JSON-сериализуемые объекты). Переход на `IndexedDB` — если объём `exerciseLog` станет проблемой (отложено, не блокирует Фазу 1).
4. Экспорт/импорт JSON реализуется **сразу в Фазе 1**, а не в Фазе 2 — ТЗ считает это обязательным условием сохранности данных при партиционировании storage (Google Sites iframe vs прямой URL).
5. Мобильная адаптация (360px+, крупные тап-зоны ≥44×44px) — обязательное требование ко всем экранам Фазы 1, не отдельная задача.

## Архитектура

- **Роутинг**: простой hash-роутер (`#/login`, `#/onboarding`, `#/home`, `#/workout`), без внешних библиотек.
- **Состояние**: один модуль `state.ts` с объектом `AppState` в памяти; persistence-слой синхронизирует нужные срезы с `localStorage` при каждом изменении (debounce не нужен — объём данных мал).
- **Рендер**: каждый экран — модуль с функцией `render(container: HTMLElement)`, вызывается роутером; повторный рендер — полная перерисовка контейнера экрана (без virtual DOM, экранов немного).
- **Файловая структура** (ориентир):
  ```
  src/
    main.ts            — bootstrap, роутер
    state.ts            — AppState, чтение/запись localStorage
    exportImport.ts      — сериализация/десериализация всего состояния в JSON
    exercises/
      loader.ts          — загрузка exercises.json + ru-dict.json
      filter.ts          — фильтрация по мышцам/оборудованию/травмам
    program/
      splitPicker.ts      — выбор сплита по дням в неделю
      exercisePicker.ts    — подбор упражнений под бюджет времени
      progression.ts       — линейная/двойная прогрессия, дэлоад, оценка 1ПМ (Эпли)
    screens/
      login.ts
      onboarding.ts
      home.ts
      workout.ts
    ui/                 — общие мелкие компоненты (кнопка, таймер-виджет)
  scripts/
    build-exercises.ts   — Node-скрипт, нормализует free-exercise-db → exercises.json (запускается один раз при сборке датасета, не на клиенте)
  public/
    exercises/           — картинки из free-exercise-db
  ```

## Модель данных (localStorage, ключ на каждую сущность)

```ts
type Auth = { login: string; passwordHash: string /* SHA-256 hex */ };

type Profile = {
  age?: number; sex?: 'male' | 'female';
  heightCm: number; weightKg: number;
  measurements?: { waist?: number; chest?: number; hips?: number; biceps?: number; thigh?: number };
  goal: 'mass' | 'fatloss' | 'strength' | 'fitness' | 'maintenance';
  experience: 'beginner' | 'intermediate' | 'advanced';
  daysPerWeek: number; // 2-6
  sessionDurationMin: number;
  equipment: 'full_gym' | 'home_dumbbells' | 'bodyweight';
  preferredStartTimes: Record<string, string>; // день недели -> "HH:MM", используется в Фазе 2 для расписания
  injuries?: string; // свободный текст, ключевые слова исключают зоны
};

type ProgramExercise = {
  exerciseId: string;
  sets: number; repsMin: number; repsMax: number;
  targetWeightKg: number | null; // null = bodyweight
  restSec: number;
};

type Program = {
  split: 'fullbody' | 'upper_lower' | 'ppl';
  days: { dayIndex: number; exercises: ProgramExercise[] }[];
  currentWeek: number;
  phase: 'linear' | 'double_progression' | 'deload';
  estimatedOneRepMax: Record<string, number>; // exerciseId -> кг, по формуле Эпли
};

type SetLogEntry = { planned: { weightKg: number | null; reps: number }; actual: { weightKg: number | null; reps: number }; done: boolean };
type WorkoutLog = { date: string; dayIndex: number; exercises: { exerciseId: string; sets: SetLogEntry[] }[]; durationMin: number; totalTonnageKg: number };

type ExerciseLog = WorkoutLog[];

type Settings = { units: 'metric' | 'imperial' }; // тема/пороги напоминаний добавятся в Фазе 2
```

## Модуль базы упражнений

- Источник — `free-exercise-db` (Unlicense), вендорится в `public/exercises`.
- `scripts/build-exercises.ts` (запускается разработчиком один раз при подготовке датасета, не на клиенте в рантайме) нормализует исходный JSON в компактный `exercises.json`: id, группа мышц (основная/вторичные), оборудование, уровень, инструкция (EN), путь к первому фото последовательности.
- `ru-dict.json` — ручной словарь перевода названий для ~150–200 самых используемых упражнений. Остальные — английское название как fallback (без блокировки релиза, как явно разрешает ТЗ).
- `exercises/filter.ts` — чистые функции фильтрации по группе мышц, доступному оборудованию, исключённым по травмам зонам (простой поиск ключевых слов в `injuries`, без медицинской логики).

## Генератор программы (детерминированный, без ИИ)

Чистые функции, без побочных эффектов, легко покрываются юнит-тестами:

- `pickSplit(daysPerWeek): Split` — по правилам раздела 5.3 исходного ТЗ (2 дня → фулбоди×2, 3 → фулбоди×3 или PPL, 4 → upper/lower×2, 5–6 → PPL).
- `pickExercises(day, equipment, excludedMuscles, timeBudgetMin, goal): ProgramExercise[]` — бюджет времени = число рабочих подходов × (время подхода + отдых) + переходы (~1–2 мин/станция); приоритет 1–2 базовых + 1–2 изолирующих на группу мышц; диапазон повторов/подходов зависит от цели (сила 3–6×3–5, гипертрофия 6–12×3–4, похудение 12–20×2–3).
- `applyWeeklyProgression(program, lastWeekLog): Program` — реализует всю логику раздела 5.3:
  - недели 1–4: линейная прогрессия (+2.5–5% при полном выполнении, дэлоад −10% при 2 срывах подряд);
  - выход на плато (2+ недели без роста) → двойная прогрессия (растим повторы до верхней границы, затем вес и вниз по повторам);
  - каждые 5–6 недель — принудительный дэлоад (объём/интенсивность −40–50%);
  - обновление оценочного 1ПМ по формуле Эпли (`1ПМ ≈ вес × (1 + повторы/30)`) на основе фактических логов;
  - для каждого изменения веса — короткое текстовое объяснение («ты выполнил все подходы на прошлой неделе — вес увеличен»), хранится вместе с `program` для показа в UI.
- Повышение уровня (новичок → средний → продвинутый) — по стажу стабильного прогресса (4–6 недель без срывов), увеличивает вариативность подбора упражнений в `pickExercises`.

## Экран тренировки

- Список упражнений на сегодня (из `program.days[currentDay]`) с картинкой, целевыми подходами/повторами/весом.
- Кнопка «Готово ✓» на подход → отмечает `SetLogEntry.done = true`, с возможностью инлайн-правки факт. веса/повторов перед подтверждением.
- После отметки подхода — автостарт таймера отдыха (значение из `restSec`, ±15 сек кнопками), сигнал по окончании через Web Audio API (работает в iframe, в отличие от Notification API).
- Общий таймер сессии: прошло / расчётный остаток (`sessionDurationMin` из профиля).
- «Заменить упражнение» — подбор аналога той же группы мышц/оборудования из базы упражнений.
- «Завершить тренировку» → сохраняет `WorkoutLog` в `exerciseLog`, показывает сводку (тоннаж, время), пересчитывает `estimatedOneRepMax`.

## Экспорт/импорт данных

`exportImport.ts`: `exportAll(): Blob` — сериализует `{ profile, program, exerciseLog, settings, auth }` (пароль остаётся хэшем, не открытым текстом) в один JSON, отдаёт как файл для скачивания. `importAll(json: string)` — валидирует структуру (наличие обязательных полей, разумные типы) и полностью перезаписывает `localStorage`, с подтверждением у пользователя перед перезаписью (необратимое действие).

## Обработка ошибок и краевые случаи

- Пустой/повреждённый JSON при импорте → понятное сообщение об ошибке, импорт не применяется (не оставляем состояние в промежуточном виде).
- Профиль с нереалистичными значениями (рост/вес вне разумного диапазона) — мягкая валидация на форме онбординга, не блокирует сохранение (пользователь может ошибиться и поправить позже).
- Упражнение без перевода — показываем английское название с пометкой, не ломаем рендер.
- `localStorage` недоступен (приватный режим браузера, партиционирование) — приложение должно не падать, а показать предупреждение «данные не будут сохранены между сессиями».

## Тестирование

- **Юнит-тесты (Vitest)**: `splitPicker`, `exercisePicker` (укладывание в бюджет времени), `progression` (все ветки: успех/срыв/плато/дэлоад/переход между уровнями), формула Эпли.
- **Ручная проверка в браузере**: полный путь вход → онбординг → сгенерированная программа → тренировка → сводка, экспорт → очистка localStorage → импорт → данные восстановлены. Проверка на ширине 360px и в локальном iframe, имитирующем Google Sites.

## Критерии приёмки Фазы 1

- Анкета → сгенерированная программа соответствует количеству дней и укладывается по времени в указанную длительность.
- Повторные «успешные» тренировки → рост нагрузки по алгоритму; срывы → нет роста/снижение; каждые 5–6 недель — дэлоад.
- У каждого упражнения на экране тренировки — картинка и инструкция (на русском для топ-150–200, иначе на английском).
- Таймер отдыха стартует автоматически и корректно завершается сигналом.
- Данные сохраняются между перезагрузками страницы и полностью восстанавливаются через экспорт/импорт JSON.
- Экран входа блокирует доступ без верного пароля, позволяет сменить логин/пароль.
- Корректная работа от 360px и внутри iframe.
